# 内部のフロー

画面・API の決まりは [仕様書.md](仕様書.md) にある。ここでは、まず DB の表と列を説明し、そのあとでサーバーの中でどの処理がどの表をどう読み書きするかをまとめる。

## DB

日時はミリ秒の数（`timestamp_ms`）で持つ。型の欄の「PK」は主キー、「→」はほかの表の行を指す外部キー（DB の決まりで結び付けている）。「〜を指す」と書いた列は、DB の決まりでは結び付けていないが、ほかの表の行を指している。

### ① 予算項目DB（`main_budget_items`）・⑦ 補正予算項目DB（`revised_budget_items`）

同じ列。行は足すだけで、項目番号ごとに最新の行が今の値。収入と支出を同じ表に入れ、項目番号の頭で分ける（収入は `in01-01-01`、支出は `out01-01-01`）。

| 列 | 型 | 中身 |
| --- | --- | --- |
| `id` | text（PK） | ランダムな id |
| `term` | text | 期（第100期） |
| `round_id` | integer（`budget_rounds.id` を指す） | その行を書いた集約（予算の変更などで足した行は空のこともある） |
| `item_id` | text | 項目の内部 ID。番号が変わっても同じで、同じ項目の行を結ぶ（②③'④⑤と `budget_lines`・`entry_items` にも同じ値を持つ） |
| `item_number` | text | 項目番号（支出は `out01-01-01`、収入は `in01-01-01`。頭で収入・支出を分ける） |
| `bureau` | text | 局 |
| `team` | text | 担当（英語の略称） |
| `kan`・`kou`・`moku`・`setsu` | text | 款・項・目・節 |
| `amount` | integer | 金額 |
| `quantity` | text | 数量 |
| `unit_price` | integer | 単価（省略可） |
| `spec` | text | 仕様・詳細 |
| `vendor` | text | 取引先 |
| `remark` | text | 備考 |
| `link` | text | リンク |
| `planned_timing` | text | 執行予定時期 |
| `is_new` | boolean | 新規の印 |
| `pre_execution` | boolean | 予算前執行の印 |
| `deleted` | boolean | 削除の印（この行が最新なら、その項目はない） |
| `status` | `draft`／`approved` | 案／承認済み |
| `sort_order` | real | 並び順 |
| `created_at` | 日時 | 行を足した時刻（最新の行を決める） |
| `created_by` | text | 行を足した人のメールアドレス |

**`entries`**（執行依頼1件）

| 列 | 型 | 中身 |
| --- | --- | --- |
| `id` | integer（PK） | 連番 |
| `seq` | text（一意） | 申請番号（執行依頼 `E-001`、証憑 `R-001`） |
| `kind` | `execution`／`evidence` | 執行依頼／証憑の提出（以前の形） |
| `type` | text | 形態（振込・発注・立替・現金執行・カード決済・その他） |
| `status` | `pending`／`done` | 執行待ち／執行済み |
| `applicant_email`・`applicant_name` | text | 申請した人 |
| `department` | text | 局（略称） |
| `in_charge` | text | 担当名（自由に書く） |
| `item_number`・`item_name` | text | 項目番号・支出項目名（予算前執行は項目番号が「予算前執行」。予算にない項目は手入力の番号で、局・担当・款から候補が入る） |
| `amount` | integer | 金額 |
| `quantity` | text | 数量 |
| `deadline` | text | 振込期限・必要日・立替予定日など |
| `remark` | text | 備考 |
| `details` | JSON | 形態ごとの追加の項目。口座情報（`details.bank`）は財務局長・管理者にしか返さない。予算前執行の印（`preExecution`）と理由（`preExecutionReason`）、役員会の承認（`budgetCommitteeApproved`）、予算にない項目の款・項・目・節（`budgetPath`）もここ |
| `attachment_id` | integer（→ `attachments.id`） | 請求書などのファイル |
| `payment_method` | text | 執行したときの執行形態 |
| `executed_at`・`executed_by` | 日時・text | 執行した時刻と人 |
| `evidence_checked_at`・`evidence_checked_by` | 日時・text | 証憑を確認した時刻と人（空なら未確認。証憑が変わると空に戻る） |
| `evidence_return_comment` | text | 証憑を差し戻した理由（証憑を付け直すと空に戻る） |
| `created_at` | 日時 | 申請した時刻 |

### ③'' 出納帳DB（`cashbook_records`）

- 執行・収入から出る出入り以外に、出納帳へ手で書く記録（財務局長・管理者）
- 執行・収入の出入りはここに入れず、出納帳を開くたびに③執行依頼DB・③'収入DBから数える

| 列 | 型 | 中身 |
| --- | --- | --- |
| `id` | integer（PK） | 連番 |
| `kind` | `opening`／`transfer`／`adjust`／`check` | 期首の残高／口座間の移動／調整（利息・手数料など）／残高の照合 |
| `date` | text | 日付 |
| `account` | text | 口座（SMBC・ゆうちょ・MUFG・現金）。移動なら移動元 |
| `to_account` | text | 移動先（移動のときだけ） |
| `amount` | integer | 期首の残高・照合は数えた残高、移動は移した額、調整は増えたら正・減ったら負の額 |
| `memo` | text | メモ（調整は理由。必須） |
| `created_by`・`created_at` | text・日時 | 書いた人と時刻 |

### ③''' 帳簿DB（`manual_journals`）

- 帳簿（複式簿記）に手で入れた仕訳（財務局長・管理者）
- 執行・収入・出納帳の記録からの仕訳はここに入れず、帳簿を開くたびに作る（`journal.ts`）

| 列 | 型 | 中身 |
| --- | --- | --- |
| `id` | integer（PK） | 連番 |
| `date` | text | 仕訳の日付 |
| `memo` | text | 摘要 |
| `lines` | JSON | 行の並び。`account`（科目）・`kind`（資産／負債／純資産／収入／支出）・`debit`（借方）・`credit`（貸方）。借方の合計＝貸方の合計 |
| `created_by`・`created_at` | text・日時 | 入れた人と時刻 |

| `size` | integer | 大きさ |
| `data` | blob | 中身 |
| `created_at` | 日時 | 入れた時刻 |

**`counters`**（申請番号の連番）

- 申請番号（E-030・I-001 など）を重ならずに振る

| 列 | 型 | 中身 |
| --- | --- | --- |
| `name` | text（PK） | 連番の名前 |
| `value` | integer | 今の番号 |

## 共通

- ①予算項目DBと⑦補正予算項目DBは**行を書き換えない**。直すたびに1行足す。ただし例外が2つある。
    - **確定のとき**（`confirmRound`）：その集約の最新の行の `status` の列だけを、`draft`（案）から `approved`（承認済み）に書き換える。ほかの列は変えない。確定までに予算の変更で別の行が足されていて最新でなくなった行は、書き換えずに承認済みの写しを足す。
    - **集約の中止**（`cancelRound`）：その集約の①⑦の案の行を消す（「10. 中止」）。
- 今の値は `latestByItem` で求める。項目（`item_id`）ごとに、作った時刻（`createdAt`）と足した順（`rowid`）でいちばん新しい行を取る。削除は `deleted` の印を付けた行を足して表す。
- 項目番号の払い出しは `allocateItemNumber` にまとめる。今ある番号・昨年の参考の番号・払い出し済みの番号を避けて次の番号を選び、`issued_item_numbers`（期と項目番号が主キー）に入れる。入れられなければ別の人が先に取ったので選び直す。この表の行は集約を中止しても残し、同じ番号を二度使わない。参考からのコピーで参考と同じ番号を使うときは `claimCopiedNumber` で同じ表に入れる。
- 項目の査定の状態は、⑤査定DBのその集約・その項目（`item_id`）の最新の行で決まる。⑤に行がない項目（補正予算で写しただけのもの）は承認済みとみなす（`roundState` の `statusOf`）。
- 今の予算は、①の第100期の承認済みの最新の行のうち、削除されていないもの（`currentRows`）。
- 執行依頼で選ぶ `budget_lines` は①予算項目DBの写しで、直接は書き換えない。①が変わるたびに `rebuildCurrentBudget` で作り直す。
    - 中では `confirmSheetRows` でシートの行の形に組み直し、`parseBudgetRows` で明細にして、`replaceBudgetLines` で入れ替える。

## 1. 本予算の集約

1. **参考の取り込み**（`importReference`）
    - CSV を読んで `budget_references` の同じ種類を入れ替え、`budget_reference_files` を更新する。
    - 本予算は `BUDGET_COLUMNS`、決算は `SETTLEMENT_COLUMNS` の見出し名で読む。
2. **集約開始**（`startRound('本予算')`）
    - `budget_rounds` に1行足す（`status: collecting`）。
    - 前に確定した集約の局・部・担当を `budget_bureaus`・`budget_departments`・`budget_teams` に写す。
    - 明細は写さない。
3. **画面に出すもの**（`roundView`）
    - `roundState` で、局・担当、項目ごとの最新の行、⑤査定DBの状態を読む。
    - 担当ごとに `listed` を付ける。昨年の参考に明細があるか、この集約に項目があれば true。参考が1件もなければ全部 true。
    - 本予算の `baseAmount` は、参考の昨年の本予算の同じ項目番号の金額の合計。
    - 項目ごとに `flow`（項目番号の頭から `flowOf` で決める収入・支出）を付ける。画面の金額の合計は収入と支出を分けて足す。
4. **明細の追加・修正・削除**（`teams/[id]/items`、`items/[id]`）
    - `canEditTeam` はだれにでも true を返す（明細の入力・提出はだれでもできる）。`assertCanAddItem`・`assertCanChangeItem` で段階を確かめる。
    - `openItemOr404` は、画面で見ていた行がもう最新でなければ 409 を返す（ほかの人が先に直した場合）。
    - `writeItem` で①に `draft` の行を足し、⑤に `create`／`edit` の行を足す。
    - 追加なら `nextItemNumber` が、使っている番号（`usedNumbers`）を避けて番号を振る。収入（`flow: income`）は局の番号の頭を `in` に替えて、収入の番号の中で数える（`bureauNoForFlow`）。
5. **参考のコピー**（`teams/[id]/copy`）
    - 参考の明細を、その項目番号のまま①に `draft` で足す。
    - その番号がこの集約にあれば「コピー済み」とみなす（`referenceFor`）。
6. **提出**（`teams/[id]/submit`、`submit-all`）
    - `setStatuses(..., 'submit')` が⑤に `submit` の行を足し、状態が `submitted` になる。
7. **集約終了 → 査定開始**（`close`、`start-review`）
    - `budget_rounds.status` を `closed` → `reviewing` にする。`assertPhase` で段階の順を守る。
8. **査定**（`items/[id]/review`、`approve`、`approve-all`）
    - 承認は⑤に `approve` を足す。
    - 要修正は⑤にコメント付きの `return` を足す。担当は直して出し直し、`reply` で返信もできる。
    - `reviewing` の間に財務管理部が直した分は、⑤に `reflect` を足す。状態は変えない。
9. **確定**（`confirmRound`）
    - その集約の最新の行を①で `approved` にする（`status` の列だけ書き換える。行を書き換えない決まりの例外）。
    - 集約にない項目は、削除の行を足して消す。
    - `rebuildCurrentBudget({ settlePreExecutions: true })` で `budget_lines` を作り直し、予算前執行を付け替える。
    - `budget_rounds.status` を `confirmed` にする。
10. **中止**（`cancelRound`）
    - その集約の①⑦の案の行、⑤、局・部・担当、`budget_rounds` の行を消す（確定していない案だけなので、今の予算には響かない）。

## 2. 補正予算の集約

1. `startRound('補正予算')` で、①予算項目DBの今の値を⑦補正予算項目DBに写す。
2. 追加・修正・提出・査定は、`tableOf(round)` が⑦補正予算項目DBを返すので、1 と同じ処理が⑦補正予算項目DBに対して動く。
3. 確定では、⑦補正予算項目DBの最新の行を承認済みにし（ここも `status` の列だけ書き換える）、もとの①予算項目DBと変わった行だけ（`sameItem` で比べる）を①に写す。そのあと `budget_lines` を作り直す。

## 3. 予算の変更（②予算変更申請DB）

1. 申請（`changes`）
    - `canRequestChange` で、割り当てられた人か財務管理部であることを確かめる（集約の明細と違い、だれでもはできない）。
    - `checkChange` で中身を確かめ、`assertNoPending` で同じ項目に承認待ちの申請がないことを確かめる。
    - ②（`budget_change_requests`）に `pending` で1行足す。
2. 承認（`applyChange`）
    - ①予算項目DBに新しい行を足す。補正予算の集約中なら⑦補正予算項目DBにも足す。
    - そのあと `rebuildCurrentBudget` で `budget_lines` を作り直す。
3. 財務管理部が直接直したときも、同じ `applyChange` を通り、②予算変更申請DBに記録が残る。

## 4. 執行依頼（③執行依頼DB）

1. `entries/index.post`
    - multipart の `payload` を `shared/schemas.ts` の決まりで確かめる。
    - `resolveBudgetLines` で選んだ `budget_lines` の明細を取る。
    - 予算にない項目は明細を選ばず、款（必須）・項・目・節を `details.budgetPath` に、手入力の項目番号を `item_number` に入れる。項目番号の候補は `budget/next-number` が、局・担当・款から `nextItemNumber` で出す（予算と、これまでの予算にない執行依頼の番号を避ける）。
    - `counters` で申請番号を振り、`entries` と `entry_items` に入れる。
    - 予算より1万円以上多いときは、役員会の承認（`budgetCommitteeApproved`）を求める。
2. 予算前執行（`preExecution: true`）
    - 明細を選ばず、項目番号を「予算前執行」にする。`details.preExecution` に印を付ける。
    - 予算前執行が必要な理由（必須）を `details.preExecutionReason` に入れる。
    - `recordPreExecution` で④予算前執行DBに `approved` で記録する（理由も `reason` に写す）。
3. 本予算の確定で、`settlePreExecutions` が付け替える。
    - 局・担当が同じで、支出項目名が明細の名前（`label`）か款・項・目・節のどれかに合う明細を探す。
    - 見つかれば、`entry_items` を足し、`entries.itemNumber` をその番号にし、④予算前執行DBを `settled` にする。
    - 見つからなければ、予算外のまま `settled` にする。
4. 台帳では、執行、証憑（`evidence_files`）、執行額（`entry_items.actualAmount`）を入れていく。
5. 証憑の確認（`entries/[id]/evidence-check`、財務局長・管理者）
    - 対応済み（`status: done`）で証憑があれば確認待ち。`confirm` で `evidence_checked_at`・`evidence_checked_by` を入れて完了にする。
    - `return` は理由を `evidence_return_comment` に入れて差し戻す。`undo` は確認済みを取り消す。
    - 証憑を付ける（`evidences.post`）と、確認と差し戻しの理由を空に戻す。証憑を外す・執行待ちに戻すと、確認を空に戻す。

## 5. 収入（③'収入DB）

1. 記録（`incomes/index.post`、だれでも）
    - `incomeSchema` で確かめる。収入の予算明細を選んだら、その明細が `budget_lines` にあり、項目番号が `in` から始まることを確かめる。
    - 予算にない収入は、款（必須）〜節を `details.budgetPath` に、手入力の項目番号（`in` から）を `item_number` に入れる。候補は `budget/next-number?flow=income`。
    - `counters` で `I-001` の番号を振り、`income_records` に `pending` で入れる。ファイルがあれば `income_files` に1件目の証憑として付ける。
2. 証憑（`incomes/[id]/files`）：だれでも付けられ、外せるのは付けた本人と財務局長・管理者。
3. 入金の確認（`incomes/[id]/confirm`、財務局長・管理者）：`done` にして `confirmed_at`・`confirmed_by` を入れる。戻すと `pending` に戻して空にする。
4. 取り消し（`DELETE incomes/[id]`）：確認待ちの間の記録した本人と、財務局長・管理者。証憑とファイルも消す。
5. 執行依頼（`resolveBudgetLines`）では、収入の明細は選べない。

## 5'. 出納帳（`cashbook.ts`、財務局長・管理者）

1. 出金：対応済みの依頼（`entries` の `done`）を、執行した日（`executed_at`、日本時間）に出す。
    - 口座は `payment_method` から決める（`accountOfPayment`）。振込（SMBC）・振込（ゆうちょ）はその口座、口座引落は SMBC、デビット（MUFG）は MUFG、現金執行と立替は現金。
    - 金額は `amount`、なければ明細ごとの執行額の合計。
    - 口座が決まらない（その他など）・金額が分からない依頼は、出納帳に入れずに「出納帳に入っていない記録」に出す。
2. 入金：確認済みの収入（`income_records` の `done`）を入金日に出す。振込は `account` の口座、現金は現金。その他と、口座の入っていない振込は「出納帳に入っていない記録」に出す。
3. ③''出納帳DBの期首の残高・移動（移動元から出金、移動先へ入金）・調整を足す。
4. 日付、同じ日の中は 期首の残高 → 収入 → 移動・調整 → 執行 の順に並べ、口座ごとの残高を足していく。
5. 残高の照合（`check`）は、その日の終わりの帳簿の残高と比べて差を出す。帳簿の残高は開くたびに計算し直すので、あとから執行・収入を直すと差も変わる。
6. 執行待ちの依頼・立替の金額の合計は、これから出ていくお金として別に出す（残高には入れない）。

## 6. 決算（`settlement.ts`）

1. 対応済みの依頼を、`entry_items.lineKey` で `budget_lines` の支出の明細ごとにまとめる（`settledLines`。収入の明細は使わない）。
2. 執行額を足し、数量をまとめ（`sumQuantities`）、取引先をつなぐ。
3. `budget_lines` にない分は「予算にない項目」にまとめる。予算にない項目として手入力した依頼は、`details.budgetPath` の款・項・目・節と担当を出す。
4. 仕様は `budget_sheet_rows` から拾い、「支出詳細」「証憑（支出）」「執行一覧」のシートを組む。
5. 確認済みの収入を、`line_key` で収入の予算明細ごとに足して「収入詳細」のシートを組む（`incomeLines`・`incomeTable`）。予算にない収入は「予算にない収入」の局にまとめ、`details.budgetPath` の款〜節と担当を出す。

## 7. DB の形の変え方

1. 表の形の変更とデータの移し替えは、`server/db/migrations/` の番号付き SQL で行う。
2. 手元では、`server/plugins/migrate.ts` が開発サーバーの起動時（とサーバーのファイルを直したとき）に流す。
3. 本番の Turso では、Vercel のビルドで `drizzle-kit migrate` が流す。
