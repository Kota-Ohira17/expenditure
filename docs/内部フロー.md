# 内部のフロー

画面・API の決まりは [仕様書.md](仕様書.md) にある。ここでは、サーバーの中でどの処理がどの表をどう読み書きするかをまとめる。

## 共通の決まり

- ①（`main_budget_items`）と⑦（`revised_budget_items`）は**行を書き換えない**。直すたびに `writeItem` が1行足す。ただし例外が2つある。
  - **確定のとき**（`confirmRound`）：その集約の最新の行の `status` の列だけを、`draft`（案）から `approved`（承認済み）に書き換える。ほかの列は変えない。確定までに予算の変更で別の行が足されていて最新でなくなった行は、書き換えずに承認済みの写しを足す。
  - **集約の取りやめ**（`cancelRound`）：その集約の①⑦の案の行を消す（「10. 取りやめ」）。
- 今の値は `latestByNumber` で求める。項目番号ごとに、作った時刻（`createdAt`）と足した順（`rowid`）でいちばん新しい行を取る。削除は `deleted` の印を付けた行を足して表す。
- 項目の査定の状態は、⑤（`budget_reviews`）のその集約・その項目番号の最新の行で決まる。⑤に行がない項目（補正予算で写しただけのもの）は承認済みとみなす（`roundState` の `statusOf`）。
- 今の予算は、①の第100期（`BUDGET_TERM`）の承認済みの最新の行のうち、削除されていないもの（`currentRows`）。
- 執行依頼で選ぶ `budget_lines` は①の写しで、直接は書き換えない。①が変わるたびに `rebuildCurrentBudget` で作り直す。
  - 中では `confirmSheetRows` でシートの行の形に組み直し、`parseBudgetRows` で明細にして、`replaceBudgetLines` で入れ替える。

## 1. 本予算の集約

1. **参考の取り込み**（`importReference`）
   - CSV を読んで `budget_references` の同じ種類を入れ替え、`budget_reference_files` を更新する。
   - 本予算は `BUDGET_COLUMNS`、決算は `SETTLEMENT_COLUMNS` の見出し名で読む。
2. **集約開始**（`startRound('本予算')`）
   - `budget_rounds` に1行足す（`status: collecting`）。
   - 前に確定した集約の局・部・担当を `budget_bureaus`・`budget_departments`・`budget_teams` に写す。
   - 明細は写さない。
3. **画面に出すもの**（`roundView`）
   - `roundState` で、局・担当、項目ごとの最新の行、⑤の状態を読む。
   - 担当ごとに `listed` を付ける。昨年の参考に明細があるか、この集約に項目があれば true。参考が1件もなければ全部 true。
   - 本予算の `baseAmount` は、参考の昨年の本予算の同じ項目番号の金額の合計。
4. **明細の追加・修正・削除**（`teams/[id]/items`、`items/[id]`）
   - `canEditTeam`・`assertCanAddItem`・`assertCanChangeItem` で権限と段階を確かめる。
   - `openItemOr404` は、画面で見ていた行がもう最新でなければ 409 を返す（ほかの人が先に直した場合）。
   - `writeItem` で①に `draft` の行を足し、⑤に `create`／`edit` の行を足す。
   - 追加なら `nextItemNumber` が、使っている番号（`usedNumbers`）を避けて番号を振る。
5. **参考のコピー**（`teams/[id]/copy`）
   - 参考の明細を、その項目番号のまま①に `draft` で足す。
   - その番号がこの集約にあれば「コピー済み」とみなす（`referenceFor`）。
6. **提出**（`teams/[id]/submit`、`submit-all`）
   - `setStatuses(..., 'submit')` が⑤に `submit` の行を足し、状態が `submitted` になる。
7. **集約終了 → 査定開始**（`close`、`start-review`）
   - `budget_rounds.status` を `closed` → `reviewing` にする。`assertPhase` で段階の順を守る。
8. **査定**（`items/[id]/review`、`approve`、`approve-all`）
   - 承認は⑤に `approve` を足す。
   - 要修正は⑤にコメント付きの `return` を足す。担当は直して出し直し、`reply` で返信もできる。
   - `reviewing` の間に財務管理部が直した分は、⑤に `reflect` を足す。状態は変えない。
9. **確定**（`confirmRound`）
   - その集約の最新の行を①で `approved` にする（`status` の列だけ書き換える。行を書き換えない決まりの例外）。
   - 集約にない項目は、削除の行を足して消す。
   - `rebuildCurrentBudget({ settlePreExecutions: true })` で `budget_lines` を作り直し、予算前執行を付け替える。
   - `budget_rounds.status` を `confirmed` にする。
10. **取りやめ**（`cancelRound`）
    - その集約の①⑦の案の行、⑤、局・部・担当、`budget_rounds` の行を消す（行を書き換えない決まりの例外。確定していない案だけなので、今の予算には響かない）。

## 2. 補正予算の集約

1. `startRound('補正予算')` で、①の今の値を⑦に写す。
2. 追加・修正・提出・査定は、`tableOf(round)` が⑦を返すので、1 と同じ処理が⑦に対して動く。
3. 確定では、⑦の最新の行を承認済みにし（ここも `status` の列だけ書き換える）、もとの①と変わった行だけ（`sameItem` で比べる）を①に写す。そのあと `budget_lines` を作り直す。

## 3. 予算の変更（②）

1. 申請（`changes`）
   - `checkChange` で中身を確かめ、`assertNoPending` で同じ項目に承認待ちの申請がないことを確かめる。
   - ②（`budget_change_requests`）に `pending` で1行足す。
2. 承認（`applyChange`）
   - ①に新しい行を足す。補正予算の集約中なら⑦にも足す。
   - そのあと `rebuildCurrentBudget` で `budget_lines` を作り直す。
3. 財務管理部が直接直したときも、同じ `applyChange` を通り、②に記録が残る。

## 4. 執行依頼（③）

1. `entries/index.post`
   - multipart の `payload` を `shared/schemas.ts` の決まりで確かめる。
   - `resolveBudgetLines` で選んだ `budget_lines` の明細を取る。
   - `counters` で申請番号を振り、`entries` と `entry_items` に入れる。
   - 予算より1万円以上多いときは、役員会の承認（`budgetCommitteeApproved`）を求める。
2. 予算前執行（`preExecution: true`）
   - 明細を選ばず、項目番号を「予算前執行」にする。`details.preExecution` に印を付ける。
   - `recordPreExecution` で④（`pre_execution_requests`）に `approved` で記録する。
3. 本予算の確定で、`settlePreExecutions` が付け替える。
   - 局・担当が同じで、支出項目名が明細の名前（`label`）か款・項・目・節のどれかに合う明細を探す。
   - 見つかれば、`entry_items` を足し、`entries.itemNumber` をその番号にし、④を `settled` にする。
   - 見つからなければ、予算外のまま `settled` にする。
4. 台帳では、執行、証憑（`evidence_files`）、執行額（`entry_items.actualAmount`）を入れていく。

## 5. 決算（`settlement.ts`）

1. 対応済みの依頼を、`entry_items.lineKey` で `budget_lines` の明細ごとにまとめる（`settledLines`）。
2. 執行額を足し、数量をまとめ（`sumQuantities`）、取引先をつなぐ。
3. `budget_lines` にない分は「予算にない項目」にまとめる。
4. 仕様は `budget_sheet_rows` から拾い、「支出詳細」「証憑（支出）」「執行一覧」のシートを組む。

## 6. DB の形の変え方

1. 表の形の変更とデータの移し替えは、`server/db/migrations/` の番号付き SQL で行う。
2. 手元では、`server/plugins/migrate.ts` が開発サーバーの起動時（とサーバーのファイルを直したとき）に流す。
3. 本番の Turso では、Vercel のビルドで `drizzle-kit migrate` が流す。
